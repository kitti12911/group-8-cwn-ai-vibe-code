# จุดตัดสินใจและบทเรียน

เพิ่มทุกครั้งที่ผู้ใช้บอกว่า skill พลาด · รูปแบบ: เกิดอะไรขึ้น → ที่ถูกคือ → ใช้กับ (ทุกโปรเจกต์ / เฉพาะ ...)

## ใช้กับทุกโปรเจกต์

1. **เกณฑ์ที่มี "ลองจริง ❌"** — ผลที่คาดหวังยังยึดตามเกณฑ์ ไม่ใช่ตามที่เว็บทำอยู่ ใส่หมายเหตุว่า "คาดว่าจะล้ม (เอกสารบันทึกไว้แล้ว)" เพื่อให้คนรัน test รู้ล่วงหน้า
2. **เกณฑ์ที่มีหลายค่าในข้อเดียว** (เช่น 4,999 · 5,000 · 5,001) — แยก 1 ค่า = 1 TC เพื่อให้รู้ว่าค่าไหนล้ม
3. **US ที่ความสำคัญ Could และอ้างฟังก์ชันที่เว็บยังไม่มี** (เช่น US-07 เทียบสินค้า) — ยังต้องเขียน TC ตามเกณฑ์ แต่ใส่หมายเหตุ "ฟังก์ชันยังไม่มีบนเว็บ (ดู Qx)"
4. **(v0.2 · 2026-11-06) ตัวแปร shell ถูกบล็อก** — รอบหมวด C ตั้ง `S=$SKILL_DIR` แล้วถูกระบบตรวจสิทธิ์ปฏิเสธ 2 ครั้ง → เรียกสคริปต์ด้วย path เต็มเสมอ
5. **(v0.2) ข้อมูลทดสอบยอดเงินไม่เป็นค่าจริง** — TC-16-03 เขียน "สินค้ายอดรวม 5,001 บาท" ไม่บอกว่าสินค้าอะไรกี่ชิ้น → ระบุ สินค้า × จำนวน ที่รวมได้ตรงยอดทุกครั้ง
6. **(v0.2) เลขคำถามใหม่ชนกับเอกสาร** — รอบหมวด C ต่อเลขเป็น Q26–Q34 → คำถามใหม่ใช้ `QA1, QA2, …` และประกาศในหัวข้อ 5 (สคริปต์เตือนถ้าใช้ QA ที่ไม่ได้ประกาศ หรือใช้ Q/K ที่ไม่มีในเอกสาร)
7. **(v0.2) คำเตือน "อ้าง K แต่ไม่ได้ใส่" ที่ไม่เกี่ยวจริง** — TC-23-01..06 ถูกเตือน K7 ทั้งที่ K7 เกี่ยวแค่ TC-23-03 และอธิบายไว้ท้ายไฟล์ → ใส่ `ไม่เกี่ยว:K7` ในคอลัมน์ "ขึ้นกับ" ของ TC นั้นแทน
