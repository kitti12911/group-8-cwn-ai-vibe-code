## 2. กลยุทธ์

### 2.1 เลือกชั้นทดสอบอย่างไร

| ชั้น | ใช้เมื่อ | TC ที่ใช้ชั้นนี้ |
| --- | --- | ---: |
| `unit` | ค่าขอบที่หน้าเว็บไปไม่ถึง (G3 = ฿2,000 พอดี · G4 = ฿3,000 พอดี · งบ ฿35,000 พอดี · เพดาน GAMER5) และกฎปัดเศษ — 29 แถวใน `TEST-DATA.md` ข้อ 6 ที่เขียนว่า `unit` | 11 |
| `api` | กฎเงินทุกแบบ สถานะออเดอร์ สิทธิ์ และทุกอย่างที่ต้องยิงพร้อมกัน — เร็วและนิ่งกว่า UI | 67 |
| `ui` | สิ่งที่ลูกค้าต้อง **เห็น** หรือ **กด**: ป้าย ราคาขีดฆ่า ปุ่มที่กดไม่ได้ ข้อความเหตุผล นับถอยหลัง | 51 |

> รวมกันเกิน 105 เพราะ TC ที่เขียนว่า `api+ui` หรือ `unit+ui` ถูกนับทั้งสองชั้น — ชั้น `api` พิสูจน์ตัวเลข ชั้น `ui` พิสูจน์ว่าลูกค้าเห็นและกดได้จริง

กฎ: **ถ้าพิสูจน์ที่ `api` ได้ ห้ามไปทำที่ `ui`** — UI test ที่ตรวจตัวเลขซ้ำกับ API ทำให้ชุดทดสอบช้าและเปราะโดยไม่เพิ่มพลังการจับบั๊ก

### 2.2 ข้อมูลตั้งต้นและการแยกกันของ test

- ทุกไฟล์ test เรียก `POST /api/test/reset` ใน `beforeEach` → ข้อมูลกลับเป็น `TEST-DATA.md` และเวลาเว็บกลับเป็น **ศุกร์ 13 พ.ย. 2026 10:00:00** (T-01)
- ล็อกอินด้วย header `X-Test-User: C3` แทนการกรอกฟอร์ม ยกเว้น TC ที่ทดสอบฟอร์มล็อกอินเอง (TC-ACCT-06)
- test ที่ยิงพร้อมกันใช้ `GPU-V57` (เหลือ 1 ใบ) เท่านั้น เพื่อให้ผู้ชนะมีได้คนเดียวแน่นอน
- **ห้าม** test ข้อใดพึ่งผลของ test ข้ออื่น — รันเรียงหรือสลับลำดับต้องได้ผลเดียวกัน

### 2.3 เวลา

เวลาเป็นตัวแปรของกฎถึง 5 ข้อ (flash sale · ล็อกราคา · กันของ 30 นาที · คืนของ 7 วัน · ใบเสนอราคา 7 วัน) จึง **ห้ามใช้นาฬิกาจริง**

```
POST /api/test/clock  { "now": "2026-11-13T12:59:59+07:00" }
```

TC ที่ต้องให้เวลาเดินเอง (นับถอยหลัง) ใช้ `{"running": true}` และยืนยันด้วย `GET /api/test/clock`

## 7. วิธีรัน

```bash
docker compose up -d --build                       # ยกเว็บทั้งชุด (http://localhost:3000)
cd backend && go test ./internal/...               # TC ชั้น unit
cd e2e && npm ci && npx playwright test            # TC ชั้น api + ui ทั้ง 3 เบราว์เซอร์
cd e2e && npm run test:race                        # TC-RACE-01…04 (ขั้น 2)
cd e2e && npm run test:property -- --seed 2026     # TC-PROP-01…06 (ขั้น 3)
BUG_MODE=1 docker compose up -d --build backend    # รันแผนกับบั๊กที่ฝังไว้ แล้วเขียน BUG-HUNT.md
```

ผลสรุปทุกรอบอยู่ที่ `e2e/index.html` · TC ที่แดงและการตัดสินว่าเป็นบั๊กของใครอยู่ที่ `e2e/triage.json`
