### ทำไมไม่ใช้ Stryker หรือ gremlins

| เครื่องมือ | ผล |
| --- | --- |
| **Stryker** | ใช้กับ JavaScript/TypeScript · โมดูลกฎของร้านนี้เป็น **Go** จึงใช้ไม่ได้ |
| **gremlins** (`go-gremlins/gremlins`, build `dev`) | ติดตั้งสำเร็จ แต่รันกับ Go 1.27 แล้วไม่พบ mutant เลย — `Gathering coverage... done · No results to report` ทั้งแบบระบุ package และ `./...` |
| **เขียนเอง** | ควบคุมได้ว่า mutate อะไรบ้าง อธิบายได้ทุกบรรทัด และ**ข้าม string literal กับคอมเมนต์** เพื่อไม่ให้ได้ mutant ขยะ |

> การบ้านอนุญาตให้ "แยกกฎเป็นโมดูลที่ test ได้โดยไม่ต้องขึ้นเว็บ แล้วเขียนเหตุผลไว้ในรายงาน" — `internal/pricing` และ `internal/compat` เป็น pure function (เวลาเป็นพารามิเตอร์ ไม่มีฐานข้อมูล) จึงรัน mutant ได้ 184 ตัวใน 8 นาที แทนที่จะต้องยกเว็บใหม่ทุกตัว

## 7. บทเรียน · ตัวเลขไหนบอกความจริงได้มากกว่า

| ตัววัด | ผล | เชื่อได้แค่ไหน |
| --- | --- | --- |
| `BUG_MODE=1` "จับได้ 3/3" | 100% | **ต่ำ** — บั๊กมี 3 ตัว และ **AI ตัวเดียวกับที่สร้างเว็บเป็นคนเลือก** จึงเลือกบั๊กในที่ที่ตัวเองรู้ว่าเอกสารเขียนไว้ชัด |
| mutation score รอบ 1 | 56.0% | **สูงกว่า** — mutant 184 ตัวไม่มีใครเลือก ได้จากการแก้โค้ดทีละจุดแบบเครื่องจักร |
| ส่วนต่างรอบ 1 → 3 | +22.8 จุด | **สูงที่สุด** — บอกว่าแผนมีรูตรงไหนบ้าง และอุดได้จริงกี่รู |

**จุดที่น่าตกใจที่สุด:** แผนทดสอบจับบั๊กที่ AI ฝังไว้ได้ครบ 3/3 แต่ mutation บอกว่าตอนนั้นแผน **ฆ่า mutant ได้แค่ 56%** — สองตัวเลขนี้มาจากเว็บชุดเดียวกัน วันเดียวกัน · "3/3" จึงไม่ได้แปลว่าแผนแข็งแรง มันแปลแค่ว่าแผนครอบ 3 จุดที่คนฝังบั๊กเลือกไว้

**สิ่งที่ mutation เจอแต่ `BUG_MODE=1` ไม่เจอเลย:**
ฟังก์ชันทั้งฟังก์ชันที่ไม่มี test (`Reship` · `UnitPrice` · `MemberPrice` · `FlashWindow`) — บั๊กที่ฝังไว้ทั้ง 3 ตัวอยู่ในเส้นทางที่ตาราง quote เดินผ่านอยู่แล้ว จึงไม่มีทางเผยให้เห็นว่ามีโค้ดกฎอีก 4 ฟังก์ชันที่ไม่เคยถูกแตะเลย
