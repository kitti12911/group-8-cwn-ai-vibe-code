## 3. พรอมต์ (วางได้เลยในเซสชันใหม่)

```text
สร้างเว็บร้านขายชิ้นส่วนคอมพิวเตอร์ "บิตบ้าน" จากเอกสารที่แนบมา

สถาปัตยกรรม
- 3 container ใน docker compose เดียว: db (PostgreSQL 16) · backend (Go) · frontend (Vite + React + TypeScript เสิร์ฟด้วย nginx)
- เข้าเว็บที่ http://localhost:3000 · nginx ส่ง /api/* ต่อให้ backend:8080 · db เปิดพอร์ต 5434 ให้เครื่องเรา
- backend มี healthcheck · frontend รอจน backend healthy ก่อนค่อยขึ้น
- `docker compose up -d --build` คำสั่งเดียวต้องได้เว็บที่ใช้งานได้ และข้อมูลตั้งต้นตรง TEST-DATA.md

ทำตาม API-CONTRACT.md ทั้งไฟล์แบบตรงตัวอักษร
- endpoint ทุกตัว · รูปแบบ Quote ทุกฟิลด์ · รหัส error ทุกตัว · data-testid ทุกชื่อ · route ของหน้าเว็บทุกอัน
- ถ้าเห็นว่าสัญญาข้อไหนทำไม่ได้ ให้บอกก่อน ห้ามเปลี่ยนเอง

กฎเงินและกฎร้าน
- ทำตาม REQUIREMENTS.md ข้อ 2 ทุกข้อ และตารางสมมติฐาน A-01 ถึง A-42 ท้ายไฟล์
- เงินเป็นจำนวนเต็มทุกขั้น ห้ามใช้ float · ส่วนลดที่เป็น % ให้ปัดลงเป็นบาทเต็ม
- แยกโมดูลกฎออกมาเป็น pure function (คิดราคา · ความเข้ากันได้) ที่ test ได้โดยไม่ต้องมีฐานข้อมูล
  แล้วเขียน unit test ที่ใช้ตาราง quote ใน TEST-DATA.md ข้อ 5 ทุกแถวเป็นชุดตรวจ

การกันของ (สำคัญที่สุด — เป็นปัญหาที่ร้านเคยเจอจริง ดู INTERVIEW.md ข้อ "เรื่องที่เคยเกิด")
- การตัดจำนวนต้องเป็นคำสั่งเดียวที่เช็กและบันทึกพร้อมกัน ห้าม SELECT แล้วค่อย UPDATE
- ใส่ CHECK constraint กันจำนวนติดลบเป็นด่านสุดท้าย
- สิทธิ์ "คนละ 1 ใบต่อล็อต" และ "NEWBIT200 ครั้งเดียวต่อบัญชี" ให้กันด้วย unique index
- ล็อกแถวเรียงตาม SKU เสมอเพื่อกัน deadlock
- ทั้งหมดต้องอยู่ใน transaction เดียวกับการสร้างออเดอร์ ถ้าชิ้นใดไม่พอ ต้องไม่มีออเดอร์เกิดขึ้นเลย

โหมดทดสอบ (TEST_MODE=1)
- POST /api/test/reset  ล้างและ seed ใหม่ตาม TEST-DATA.md · เวลาเว็บกลับเป็น 2026-11-13T10:00:00+07:00 แบบหยุดนิ่ง
- POST /api/test/clock  ตั้งเวลาเว็บ · รองรับ running: true ให้เดินต่อตามเวลาจริง
- GET  /api/test/clock · GET /api/test/bug-mode
- header X-Test-User: <รหัสลูกค้า> ใช้แทนการล็อกอินได้
- งานเบื้องหลังต้องปล่อยของที่หมดเวลาและเปิดล็อตใหม่ภายใน 5 วินาที โดยไม่ต้องมีคนเปิดหน้าเว็บ

โหมดบั๊ก BUG_MODE
- 0 = ปกติ ไม่มีบั๊ก
- 1 = ฝังบั๊กไว้ 3 ตัวในโมดูลกฎ แต่ละตัวต้องขัดกับ BR คนละข้อ เห็นได้ผ่าน API และต้องเป็นบั๊กที่
      "ค่าขอบ" หรือ "ลำดับการคิด" ไม่ใช่ทำให้เว็บล่ม · เขียนเฉลยไว้ใน backend/BUGS.md
- 2 = เว้นไว้ให้ทีมอื่นฝังบั๊ก (โค้ดต้องรับค่า 2 ได้โดยไม่พัง แต่ไม่มีบั๊กของเราเอง)
- ทุกหน้าเว็บต้องมี <body data-bug-mode="0|1|2">

หน้าเว็บ
- ทำทุก route ใน API-CONTRACT.md ข้อ 5 · ภาษาไทย · เวลา 24 ชั่วโมง เขตเวลา Asia/Bangkok
- ใช้ได้บนจอกว้าง 375px โดยไม่มีการเลื่อนซ้ายขวา
- หน้าจัดสเปกต้องปิดตัวเลือกที่ใส่ด้วยกันไม่ได้พร้อมบอกเหตุผล ส่วนพาวเวอร์ไม่พอให้เตือนอย่างเดียว ห้ามถอดของให้เอง
- นับถอยหลังบนหน้าจ่ายเงินต้องใช้เวลาของเซิร์ฟเวอร์ ไม่ใช่นาฬิกาเครื่องลูกค้า

ห้าม
- ห้ามแก้ตัวเลขใน TEST-DATA.md ให้ตรงกับที่โค้ดคำนวณได้ — ถ้าไม่ตรง ให้รายงานว่าไม่ตรงตรงไหน
- ห้ามเปลี่ยนชื่อ data-testid หรือรหัส error โดยไม่แก้ API-CONTRACT.md ก่อน
```
